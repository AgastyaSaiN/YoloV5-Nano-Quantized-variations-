Quantizing YOLOv5n to INT8 while Keeping the Detection Head in FP32

Benchmark report  |  Model: YOLOv5nu (ultralytics)  |  Test set: 1,000 held-out COCO val2017 images  |  Runtime: ONNX Runtime, CPU

Summary. We compressed the YOLOv5 nano object detector from 32-bit to 8-bit numbers (INT8 quantization) and left the final detection layer untouched. The best version, v1, is 46% smaller and 19% faster than the original, and loses only 0.9% of its accuracy (0.332 vs 0.335 mAP50-95).

The detection layer matters. When we compressed it as well, accuracy fell to zero. Section 5 explains why.

1. What was tested

Quantization stores a model's numbers in a smaller format so the file is smaller and inference is faster, at the cost of some precision. We built four compressed variants of YOLOv5n and one deliberate failure case, then scored all of them against the original on the same 1,000 labelled photos. None of those photos were used to calibrate the compressed models.

2. The variations: what we tried and what happened

Two things can be changed when quantizing. One is calibration: how the 256 available INT8 steps are spread over each layer's range of values. The other is exclusion: which layers are left in full precision. Everything except the control below keeps the detection layer in FP32.

5. Why the detection layer must stay in FP32

The detection layer produces one output table that holds two kinds of numbers side by side: box positions, which run up to 640, and confidence scores, which lie between 0 and 1. INT8 offers only 256 distinct values, and the whole table has to share them.

To make 640 fit, each step has to be about 2.5 wide. Every confidence score, being below 1, then rounds to the same value, zero, and the model appears to detect nothing. That is exactly what the control model does.

The fix is to leave the detection layer in full precision. For v1 to v4 we checked each of its 19 convolutions against the original: the weights are FP32 and numerically identical, and no quantize or dequantize operations sit inside the layer. The small accuracy loss that remains comes from the rounding in the layers before it.

6. Recommendation

Use v1 (models/int8/v1_percentile_head.onnx). It has the smallest file, near-original accuracy, and is among the fastest. v3 is equivalent. v4 costs about 1.1 MB more for no gain in accuracy, and v2 is slightly less accurate.

7. Limitations

  • Ranking v1 to v4 is not reliable. They differ by under 0.5%, which 1,000 test images cannot separate. The firm conclusions are that a protected head costs about 1% accuracy and an unprotected one destroys the model.
  • Speed is approximate. It comes from one CPU and 50 timed runs per model. GPUs, phones and other runtimes will behave differently.
  • Data. Calibration used 100 COCO images, and testing used everyday COCO photos. Calibrate and test on your own images before deploying.
  • Scope. This covers the ONNX route only. PyTorch-native quantization was not evaluated.

8. What we have not tried yet

The variations above were deliberately mild. These are the more drastic options, roughly in order of how promising they look:

  • Mixed precision by sensitivity. Measure how much each individual layer hurts accuracy when quantized, then protect only the worst ones. This is likely to beat the blunt "protect the head" rule.
  • FP16 detection layer. Keep the head at 16-bit instead of 32-bit, for a smaller file (about 1.4 MB less).
  • Quantization-aware training. Fine-tune with quantization simulated. It usually recovers accuracy but needs training data and time.
  • Lower bit widths. 4-bit weights for the backbone, which would shrink the file further and likely cost more accuracy.
  • Partial backbone quantization. Quantize only some stages, to see where accuracy starts to degrade.
  • Other hardware. Time the models on a GPU, phone or Raspberry Pi, where INT8 speed-ups can be much larger than on this CPU.

Appendix. Terms

mAP50-95
The standard accuracy score for object detectors, from 0 to 1. It rewards finding objects, labelling them correctly and drawing tightly fitting boxes, judged at overlap thresholds from 50% to 95%.
mAP50
The same score using only the lenient 50% overlap threshold.
Precision
Of the objects the model reports, the fraction that are correct. High precision means few false alarms.
Recall
Of the objects actually present, the fraction the model finds. High recall means few misses.
FP32 and INT8
32-bit floating-point numbers (precise) and 8-bit integers (compact). Quantization converts the former to the latter.
Calibration
Running sample images through the model to measure each layer's typical value range, so INT8 steps can be placed sensibly. Min-max uses the extremes seen; percentile ignores rare outliers.
Detection layer (head)
The final layer, which converts internal features into box coordinates, class labels and confidence scores.
